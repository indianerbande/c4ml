# C4thedral 0.1.0-beta.5

[English](0.1.0-beta.5.md) | [Deutsch](../../de/releases/0.1.0-beta.5.md)

Status: In preparation (not tagged yet)

Date: 2026-09-04

This source beta follows an architecture and implementation review. The
layered design was confirmed; the review found that the evidence layer mostly
checked structure instead of behavior, which had let several rendering and
editor defects pass the gate. Every item below is covered by a test that fails
on the previous code.

## Rendering corrections

- Generated legends now list every drawn notation kind. Previously
  `legend = generated` produced only the "Notation" heading in every diagram.
- Automatic routes keep the layout engine's boundary attachment points for
  box-filling shapes. Several connections entering one side no longer collapse
  onto the side's centre, and arrowheads enter the element perpendicularly
  instead of sliding along its edge. Shapes with an open outline still use
  their declared Port anchor.
- Relationship labels take part in the layout: the engine reserves their
  footprint between layers and reports the reserved position, so labels no
  longer sit on the elements they connect or on each other.
- Layouts are stable across runs. ELK read seed `0` as "pick a seed", which
  made the same request alternate between layouts on one engine instance and
  let `render --all` differ from `render --view`.
- Geometry that placement moves to negative coordinates is no longer clipped;
  the canvas grows around every node, route point, and label.
- Compiler-stage errors name the objects they are about; diagnostics are
  located through those subjects instead of searching the message text for
  identifiers.

## Relationship projection in static views

Relationships are declared once, where they happen. Static views now lift
each endpoint to its nearest visible ancestor: a Container → Container
relationship between two Software Systems appears between the systems in a
System Context or Landscape View, a Person → Component relationship appears as
Person → Container in a Container View. Implied connections are drawn dashed,
listed in the legend, and reveal every declaration they represent from the
workbench. `relationships = declared` restores the previous behavior per view.
The specification records the projection rule in §6.

## Workbench corrections

- Placement, route, and semantic authoring edits addressed to a project
  document other than the active one are applied after the editor presents
  that document, not from a microtask that ran before the model switch. Undo
  is bound to the document that received the change and returns to it.
- Cross-document reveals from Problems, Output, the preview, and the geometry
  inspector wait for the target document as well.
- The wizard's "new document" path asks before discarding unsaved work, like
  Open and Close do.
- The geometry inspector reports layout coordinates, so a pin generated from
  the current position no longer drifts by the scene offset.

## Evidence

- `apps/cli/test/rendered-examples.test.ts` renders every executable example
  through the production pipeline and checks geometric invariants: populated
  legend, everything inside the canvas, automatic labels clear of elements and
  of each other, perpendicular boundary attachment, distinct endpoints, and
  identical output on a second run.
- The packaged desktop smoke opens a disposable copy of the multifile example,
  applies a placement change to another document than the active one, undoes
  from a different tab, and reveals a finding across documents. It now
  requires an explicit verdict; a silent exit no longer counts as a pass.
- 600 repository tests, the TypeScript gate, the Angular production build, and
  the documentation, production-editor, desktop-production, worker-bundle, and
  architecture-proof checks pass. The macOS arm64 packaged smoke, including the
  multi-document authoring round trip, passed on 2026-09-04 under Node.js
  24.15.0.

## Distribution boundary

`v0.1.0-beta.5` is a public source beta. Native installers have not been rebuilt
or revalidated on every platform for this change. Apple Developer ID signing
and notarization and Windows publisher signing remain open release
requirements.
